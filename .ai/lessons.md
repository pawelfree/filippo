# Lessons learned

Read this index before working on related areas. Add concise, evidence-based lessons here after a bug fix or other reusable finding. Put longer explanations in `lessons/YYYY-MM-DD-slug.md` and link them from the entry.

- When a CSS class sets `display`, add an explicit `[hidden] { display: none }` rule for views initially hidden by HTML. The taxonomy browser's grid rule would otherwise override the user-agent treatment of `hidden` before data loaded. Applies to browser interfaces with conditional sections.
- When validating JSON Schema with Ajv, install and register `ajv-formats` for schemas that rely on `date-time` or `uri`; Ajv does not enforce those format keywords by itself. Applies to runtime validation of profile metadata and timestamps.
- A lexical database entry may have missing or mismatched sense glosses even when its lemma and part of speech are useful. Wikidata's Italian preposition Lexeme [L1413197](https://www.wikidata.org/wiki/Lexeme:L1413197) for `attraverso` has the adverb-like gloss `trasversalmente`; verify the meaning against another source before using it as sense evidence. Applies to LexicalSense creation.
- An attested contemporary sentence is not required for every LexicalSense: the schema allows an authored example when the sense is source-backed and the sentence is checked for natural use. The `attraverso` adverb was initially deferred despite dictionary support because this distinction was missed; see the [review](runs/2026-10-25-attraverso-deferred-review.md). For an underspecified surface form, retain both direct headword readings and attested inflectional readings under their proper lemmata; see the [verb-form correction](runs/2026-10-25-attraverso-verb-form-expansion.md).
- A lexical creation result needs to identify an unresolved raw input without inventing a meaning. Use the input form and report only that it was not found in the sources checked; source unavailability is a separate outcome. Applies to unknown words in [creation.rules.md](docs/lexical_sense/creation.rules.md).
- A dictionary synonym list or translation gloss can suggest a sense without establishing that it is a current general Italian use. For contemporary LexicalSense creation, seek a direct description or contemporary usage evidence before promoting such a candidate; see the [rules update](runs/2026-10-25-contemporary-lexical-senses.md).
- When a lexical creation skill only needs to return meanings for the current input, store the Italian word or phrase directly in each sense and omit record IDs from the skill output. Any identifier needed by later persistence or exercises belongs to that later process. See the [skill output correction](runs/2026-10-25-remove-lexical-sense-output-ids.md).
- Do not assign a default output directory to an agent skill when the user has not chosen one. Return the result directly, and write files only when the caller requests a destination. Applies to [create-lexical-senses](docs/lexical_sense/create-lexical-senses/SKILL.md).
- A skill with a narrow purpose does not need a list of unrelated files it must leave untouched. State its task and source of truth; redundant prohibitions obscure the actual workflow. Applies to [create-lexical-senses](docs/lexical_sense/create-lexical-senses/SKILL.md).
- When a skill is intended to be self-contained, bundle the rules and schema it needs under `references/` and link them locally. Copied references become the skill's own version and need deliberate updates when the source documents change. Applies to [create-lexical-senses](docs/lexical_sense/create-lexical-senses/SKILL.md).
- For a skill whose batch output is consumed through OpenAI Structured Outputs, keep one API-compatible `text.format` file for the batch and check returned records against their separate record schema. A second batch schema adds maintenance without helping this workflow. Applies to [create-lexical-senses](docs/create-lexical-senses/SKILL.md).
- A skill can instruct an agent to search the web and verify pages, but the Responses API caller must enable `web_search` in `tools`; a skill file cannot grant its own tool access. Avoid hard-coding one source when the task calls for general web research. Applies to [create-lexical-senses](docs/create-lexical-senses/SKILL.md).
- Nest constructors that depend on injected classes should use explicit `@Inject(Token)` when running through tsx/esbuild; this runtime did not emit `design:paramtypes`, so Nest called `ProfileService` without its `TaxonomyService`. Cover source-mode container startup with a regression test. Applies to Nest development runtimes that transpile TypeScript without decorator metadata.
- When users select AI-generated `LexicalSense` records for persistence, keep the validated draft on the server and accept only selected indices plus permitted edits from the browser. A client-supplied full record could bypass generation and source validation. Use a database uniqueness key for deterministic retry safety, and still show existing senses for human review of semantic near-duplicates. Applies to the LexicalSense import flow.
